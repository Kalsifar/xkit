# Файлы проекта: NGINX + 3X-UI «xkit»

## xkit.sh — XKIT v4.8.0 (рекомендуется)
«Кит-меню» в стиле родного `x-ui` для Ubuntu 24.04+. После установки команда
`xkit` доступна по SSH (пункт 21 включает АВТО-меню при каждом входе по SSH).
Запуск: `sudo bash xkit.sh` (или `xkit install`).

## Два сценария использования

**Сценарий A — один сервер (5 минут).** Установка одной командой, в конце
выбрать «1) Одиночный сервер» — автопроброс инбаундов за nginx. Дальше точечные
настройки — в панели 3X-UI, пользователи — `xkit -> 4`, подписка — `xkit -> 3`,
проверка — `xkit -> 7`.

**Сценарий B — мастер + зарубежные ноды.** Та же установка, в конце выбрать
«2) Мастер с нодами»: автопроброс, затем добавление нод по SSH (3X-UI +
Reality-туннель поставятся сами). Клиентские ссылки пула балансируются между
нодами (roundRobin/leastPing/… — НОДЫ -> 4). Наблюдение: веб-дашборд (23) +
Telegram-алерты (26). Удаление последней ноды автоматически возвращает сервер
в одиночный режим (pool убирается целиком).

## Установка одной командой

**Вариант А — GitHub.** В репозитории лежат `install.sh`, `xkit.sh` и
`xkit.sh.sha256`. В `install.sh` один раз замените `YOUR_USERNAME` на свой ник,
далее на любом чистом сервере:

```bash
curl -fsSL https://raw.githubusercontent.com/НИК/xkit/main/install.sh | sudo bash
```

`install.sh` скачивает `xkit.sh`, проверяет SHA-256, отдает установщику
терминал (пароль sudo / вопросы мастера установки работают даже при
«curl | bash») и запускает `xkit install`. Пошаговая настройка такого репо
(создание, замена `YOUR_USERNAME`, sha256-канал для `xkit update`, теги,
частые проблемы) — в **[GITHUB_SETUP.md](GITHUB_SETUP.md)**.

**Вариант Б — свой сервер** (без GitHub; оба файла лежат в папке за nginx):

```bash
curl -fsSL https://ВАШ_ДОМЕН/xkit/install.sh | sudo bash
```

**Без обёртки** (два действия в одной строке):

```bash
curl -fsSL https://raw.githubusercontent.com/НИК/xkit/main/xkit.sh -o /tmp/xkit.sh \
  && sudo bash /tmp/xkit.sh install
```

Обновление до новой версии = повторить ту же команду. Субкоманды без root:
`bash install.sh help|status|health`; URL можно переопределить:
`XKIT_BASE=https://... bash install.sh` или `bash install.sh https://.../xkit.sh`.

## Обновление установленного xkit

`install.sh` запоминает источник установки (`XKIT_REPO_URL` в `/etc/xkit/xkit.env`),
поэтому на уже установленном сервере достаточно:

```bash
sudo xkit update                # из запомненного репозитория
sudo xkit update https://raw.githubusercontent.com/НИК/xkit/main   # или явно
```

`xkit update`: скачивает xkit.sh → сверяет SHA-256 с `xkit.sh.sha256` из репо →
`bash -n` → сравнивает версии (форс: `XKIT_FORCE=1`) → атомарно заменяет
`/usr/local/bin/xkit`, оставляя бэкап `.bak`. Конфиг nginx, состояние, подписки
и cron не трогаются. В меню — пункт 22.

### Удобство и Telegram-алерты (v4.5)
- **Симметрия мастер -> одиночный**: удаление ПОСЛЕДНЕЙ ноды теперь убирает
  pool-инбаунд целиком (панель + маршрут nginx + env + перегенерация подписок).
  Раньше pool оставался, а правило balancer уже исчезало из шаблона xray —
  ссылки пула продолжали работать, молча меняя exit-IP на адрес мастера.
  Явный возврат: НОДЫ -> 8 «убрать pool».
- **auto_route помечает pool-инбаунд как POOL** и не трогает его.
- **Развилка в конце установки**: одиночный / мастер с нодами / позже.
- **Строка «Режим»** в `xkit info`, `xkit status`, шапке меню и на дашборде
  (баннер одиночного режима, поле `mode` в data.json).
- **Telegram-алерты** (`xkit telegram setup`, меню 26): только то, чего 3X-UI
  не знает — нода упала/восстановилась (гистерезис: алерт со 2-й проверки
  подряд), аренда <=7 дн. и истёкшая (дедуп: раз в сутки), сертификат <=14 дн.,
  дашборд stale (>25 мин). Бот-команды и уведомления о клиентах НЕ дублируются —
  это умеет 3X-UI (один бот, один чат; сообщения xkit помечены `[XKIT]`).
  Доставка: с мастера напрямую; если api.telegram.org недоступен — через ноды
  по SSH (curl крутится на ноде, выход с её IP). Токен не попадает в argv
  (curl `-K -` читает URL из stdin). Cron каждые 10 минут
  (`/etc/cron.d/xkit-notify`); состояние алертов — `/etc/xkit/notify.state` (600).
  Выключение: `xkit telegram off`.

### Правки финального ревью №2 + GitHub-инструкция (v4.8.0)
- **node_add: EOF (Ctrl-D) на любом вводе — отмена**, а не молчаливое
  продолжение с дефолтами 22/root и попыткой коннекта к ноде (симметрия с
  v3.2.1; Enter-дефолты при живом вводе работают как раньше).
- **install.sh: `-y/--force` доезжают до xkit при запуске не от root** —
  явный проброс `XKIT_YES/XKIT_FORCE/XKIT_NO_COLOR/XKIT_NO_ANIM/
  XKIT_REPO_URL` через `sudo env` (sudo сам env не наследует, env_keep
  зависит от sudoers). Root-путь (`curl | sudo bash -s -- -y`) — через export.
- **install.sh: `warn` тоже в stderr** (симметрия с xkit.sh) — диагностика
  не попадает в пайпы/захват stdout.
- **GITHUB_SETUP.md** — инструкция хостинга на GitHub для установки одной
  строкой (см. ссылку в разделе «Установка одной командой»).

### Установка/переустановка/удаление + живой UX (v4.7.0)
- **Повторный `xkit install` на установленном сервере больше не «ставит поверх
  молча»**: preflight видит `/etc/xkit/xkit.env` и предлагает меню — 1) обновить
  скрипт (`xkit update`, состояние не трогается) 2) чистая переустановка
  (бэкап → полное удаление → установка с нуля) 3) починить поверх (пакеты/
  панель/конфиг заново, состояние — адрес, путь подписок, Telegram, дашборд —
  сохраняется и подхватывается). Раньше молча генерировался НОВЫЙ SUB_TOKEN
  (все ссылки подписок у клиентов отваливались) и save_xkit_env затирал
  TG/dash-токены нулями.
- **`xkit uninstall [--full]`**: перед удалением ОБЯЗАТЕЛЬНО делается бэкап
  (провал бэкапа = отмена), подтверждение YES (или `XKIT_YES=1`). Удаляются
  cron-задачи, nginx-сайт + reload, `/etc/xkit` (состояние, SSH-ключи нод),
  `/var/lib/xkit` (подписки, дашборд), htpasswd, UFW-deny порта панели,
  `/usr/local/bin/xkit`. `--full` дополнительно: 3X-UI (сервис, `/etc/x-ui`,
  `/usr/local/x-ui`) и `/etc/nginx/ssl`. НИКОГДА не удаляются: бэкапы
  (`/var/backups/xkit`, 14 дней), letsencrypt, nginx и чужие сайты, UFW-правила
  SSH/80/443. Ноды продолжают работать автономно.
- **`xkit reinstall`** = бэкап → uninstall --full → one_step_install: чистая
  переустановка одной командой (общий лог на всю цепочку).
- **Preflight ДО изменений**: занятые порты 80/443 с именами процессов (nginx
  будет перенастроен, чужой процесс — предупреждение), свободное место
  (<500 MB — отказ), RAM (<400 MB — предупреждение), доступ к сети; при
  предупреждениях — подтверждение.
- **Живой UX установки**: цвета гаснут при не-TTY (`curl | sudo bash | tee log`
  не мусорит ANSI-кодами), спиннер вокруг apt-get / детекта схемы панели /
  webListen (было 20-60 сек тишины), индикатор шагов `[n/7]`, полный лог
  `/var/log/xkit-install-*.log` (600) с хвостом при ошибках, trap INT/TERM
  чистит временные файлы и подсказывает путь к логу.
- **Неинтерактивный режим (CI/cloud-init)**: `XKIT_YES=1` — согласие на вопросы,
  `XKIT_FORCE=1` — установка поверх без меню; `install.sh` пробрасывает
  `-y | --yes | --force`. Для пайпа флаги идут после `--` (иначе bash съест
  `-y` как свой аргумент): `curl -fsSL .../install.sh | sudo bash -s -- -y`.
  Запуск не от root тоже работает: install.sh пробрасывает переменные через
  `sudo env` (sudo сам env не наследует).
- **Фикс по итогам ревью v4.7.0**: `warn()` пишет в stderr — предупреждения
  больше не попадают в захваченный вывод (при неработающей панели
  `PANEL_SCHEME` остаётся ровно `http`/`https`, а не «[WARN] …\nhttp»,
  ломавший api_url); общий лог reinstall не затирается фазой установки
  (обе фазы — в одном `xkit-reinstall-*.log`); `uninstall --full` сбрасывает
  failed-статус x-ui в systemctl. Правки второго ревью (node_add EOF,
  sudo env) — в списке v4.8.0 выше.

### Безопасность и надёжность (v4.6.0 — пятый аудит + наблюдения эксплуатации)
- **Инъекции закрыты**: все TCP-пробы `/dev/tcp` (5 мест в xkit, 2 в v3)
  переведены на `bash -c '..."$1"...' _ host port` — хост/порт из nodes.json
  больше не интерполируются в командную строку; SSH-пользователь ноды
  валидируется (`^[a-zA-Z_][a-zA-Z0-9_.-]{0,31}$`); install-result.env
  парсится БЕЗ `source` (awk с точным сравнением ключа — метасимволы в ключе
  безопасны); `/etc/xkit` — 0700 ДО ssh-keygen.
- **nodes_health честен про SSH**: провал SSH считается отдельно — финал
  «Туннели живы, но SSH недоступен на N нодах», а не «Все ноды живы».
- **Сироты pool-инбаундов больше не копятся**: старый pool удаляется ИЗ
  ПАНЕЛИ (новый `api_del_inbound`), а не только маршрут nginx; при сбое
  apply сообщение объясняет, что будет при повторе.
- **sub_regen под flock**: cron (раз в час) и ручной запуск не пересекаются —
  нет окна 404/битого base64 для клиентов.
- **dash_rotate**: откат htpasswd — копированием из бэкапа (не пересчётом
  openssl); сбой записи env после успешного apply кричит явно.
- **Мелочи аудита**: rand_str без SIGPIPE-хрупкости (длина гарантирована,
  энтропия сохранена), is_ipv6 → inet_pton, битый nodes.json → `[]` + warn,
  ключи алертов с «.» безопасны (awk вместо grep -v), python3 в зависимостях
  + понятная ошибка, предупреждение если креды панели не извлечены;
  notify_state_set и save_xkit_env пишут в subshell — umask не утекает
  в интерактив при сбое, провал записи env теперь честный (err, не молчаливый ok).
- **Новые алерты (`xkit telegram check`)**: СЕРВИСЫ мастера (nginx/x-ui упал/
  восстановился, гистерезис) и ДИСК (≥85% предупреждение, ≥95% тревога,
  «место освободилось») — раньше мастер сообщал только о нодах.
- **IPv6**: при глобальном v6-адресе nginx слушает и `[::]:443` + `[::]:80`
  (v6-only клиенты за CGNAT раньше не могли подключиться вовсе);
  `XKIT_V6_LISTEN=0|1|auto` — принудительный режим. Генерация проверена
  E2E-тестом с настоящим `nginx -t` в обоих синтаксисах http2 (1.24/1.25.1+).

### Безопасность и фичи (v4.4.2 — хвост четвёртого аудита)
- **dash_sanitize_inbounds: clients корректен для ВСЕХ форматов** — raw API
  (клиенты внутри settings-строки), settings-объект, `.clients`-массив
  (полу-sanitized — раньше молча давал 0), `.clients`-число, null/битое → 0.
  Функция всегда возвращает валидный JSON-массив даже на пустом входе.
- **enable:false больше не теряется**: `// true` в jq считает `false` пустым
  значением — выключенный инбаунд/пользователь на дашборде показывался как
  включённый (inbounds, users, whitelist).
- Предохраняющий комментарий у `umask 027` в dash_gen_locked (не выносить
  из subshell).

### Безопасность и фичи (v4.4.1 — четвёртый аудит: хвосты дашборда)
- **КРИТИЧНО: stale-ветка дашборда санитизирует данные при ЧТЕНИИ** — раньше
  апгрейд с v4.3 (в data.json лежали сырые инбаунды с Reality privateKey и
  UUID) + падение панели до первого успешного `dash gen` возвращали утечку:
  cron брал старый raw JSON и писал его обратно с флагом `stale`. Теперь при
  чтении старого файла данные прогоняются через санитайзер (идемпотентно),
  нераспознанный формат → пустые данные (fail-closed), плюс финальный
  sanitize перед КАЖДОЙ записью data.json как последний барьер.
- **Трафик нод и totals: total = up+down (потрачено)**, а не квота `.total`
  инбаунда (у большинства 0 = безлимит): раньше колонка «Σ» у нод показывала
  лимит, а не фактический расход. Та же формула — в санитайзере мастера.
- **dash_rotate стал атомарным**: env и htpasswd откатываются при сбое
  применения конфига — раньше nginx оставался на старом пути, а в xkit.env
  уже лежал новый токен («ротация прошла», а URL отдаёт 404).
- **Пароли больше не печатаются в stdout по умолчанию**: `xkit info` и
  сводка после операций показывают маску `********` и подсказку
  «полные реквизиты: cat /root/xkit-info.txt» — scrollback терминала,
  `tee`/`script`/CI-логи больше не собирают секреты. Полные пароли — только
  в файле 600; реквизиты при установке (интерактив) по-прежнему печатаются.
- **dash_fix_perms на не-Ubuntu**: группа берётся через `id -gn` юзера nginx
  (юзер ≠ группа), при неудаче — явный WARN (раньше молча оставались 644);
  права 750 ставятся сразу (без окна 755 в начале каждого gen), файлы пишутся
  с umask 027 — сразу 640, а не 644 до конца построения.
- **node_repin: подтверждение при смене пина** (TOFU): показываются старый и
  новый отпечаток, обновление — только по явному «y»; без tty пин не
  меняется. Молча принять новый пин после компрометации = легитимизировать
  MITM. Первый пин (при добавлении ноды) принимается без вопросов.
- Мелочи: `dash_sanitize_inbounds` идемпотентен (sanitize(sanitize(x)) ==
  sanitize(x) — proto/clients не теряются при повторном прогоне), новый
  whitelist полей users (`dash_users_whitelist`), totals в stale-ветке
  пересчитываются из sanitized-данных, `nodes_repair` считает ноды через pipe.

### Безопасность и фичи (v4.4 — третий аудит: дыры дашборда/expiry + реквизиты)
- **КРИТИЧНО: ufw на ноде при пустом MYIP** — если публичный IP мастера не
  определился (pubip/DNS/блокировки), панель ноды теперь ЗАКРЫВАЕТСЯ
  (`ufw deny NPP/tcp`), а не остаётся открытой в интернет; в выводе — готовая
  команда SSH-туннеля (`ssh -p NPORT -L NPP:127.0.0.1:NPP root@нода`).
- **КРИТИЧНО: data.json дашборда санитизируется** — раньше туда уходил полный
  JSON инбаундов: Reality `privateKey`, UUID/subId всех клиентов. Теперь только
  агрегаты (`tag/port/proto/enable/up/down/total/clients`) — утечка токена URL
  больше не означает кражу ключей. Заодно починены поля для JS (было `.proto`
  от несуществующего `.protocol` и `.clients` из необработанного `.settings`).
- **Basic Auth на дашборде**: случайные логин/пароль генерируются при установке
  (как у панели ноды), хранятся в `xkit.env` (600), хэш — в
  `/etc/nginx/.xkit-dash.htpasswd` (apr1). Браузер спрашивает логин поверх
  секретного URL — двойной барьер.
- **Сводка-реквизиты**: после установки/добавления ноды/дашборда/expiry всё
  важное печатается в терминал и сохраняется в `/root/xkit-info.txt` (600):
  панель + логин/пароль, дашборд + логин/пароль, подписки, ноды, сроки аренды.
  В любой момент: `xkit info` или пункт меню 25 (в терминале пароли
  маскируются — полные только в файле).
- **Права файлов дашборда**: `/var/lib/xkit` и `dash/` — 750 root:www-data,
  `data.json`/`index.html` — 640 (читает только nginx, а не все локальные юзеры).
- **dash_gen: flock в subshell** — раньше `exec 9>` держал lock в интерактивной
  сессии, и cron не мог обновить дашборд, пока админ сидел в меню.
- **Stale-данные**: если панель недоступна при построении, прошлый трафик не
  затирается пустотой (data.json помечается `stale: true`, страница предупреждает).
- **nodes_ensure_pool**: early-return только если nginx реально знает маршрут
  pool (grep по конфигу) — после сбоя apply пул пересоздаётся, а не остаётся
  «в реестре без маршрута». Плюс `xkit nodes repair` — переприменение всей
  конфигурации нод после сбоя (меню Ноды → 6).
- **Пин сертификата панели ноды**: при добавлении снимается sha256 публичного
  ключа (как SSH TOFU), дальше `node_api` ходит с `--pinnedpubkey` — MITM на
  master↔node API не пройдёт. Перепин после перевыпуска серта: `xkit nodes repin`.
- **expiry**: flock при записи (cron/CLI не теряют правки), заметка без табов
  (формат TSV не ломается). **`xkit dash rotate`** — новый токен URL + новый
  логин/пароль дашборда без переустановки.
- Мелочи: одна `human_bytes` (IEC, английские суффиксы — client_list снова
  показывает KiB/MiB), `_dash_ips` объявлена local, в allow-списке дашборда
  принимаются CIDR (`10.0.0.0/8`), кривые адреса молча не попадают в nginx
  (fail-closed: `deny all` остаётся), переменная `ss` в скане ноды переименована
  в `notvalid`.

### Безопасность (v4.3 — второй аудит: регрессии и дыры)
- **КРИТИЧНО (regression v4.2): ufw на ноде настраивался «вслепую»** — правила в
  quoted-heredoc не раскрывались, молча падали, а `ufw --force enable` с пустыми
  правилами отрезал SSH и туннель (loss ноды). Теперь: все переменные через env
  (`NPORT/TP/NPP`), `set -u` + `:?` (скрипт падает ДО enable), вывод `ufw allow`
  не глушится — любая ошибка правила видна и останавливает firewall до enable.
- **Скан Reality (мастер и нода)**: любой провал проверки цепочки сертификата
  (истёк/кривой SAN/unknown CA/incomplete chain) = кандидат НЕПРИГОДЕН. Раньше
  «строки Verify return code нет» трактовалось как «годен» — на плохой dest
  можно было посадить Reality.
- `xkit update` без аргументов работает из свежей SSH-сессии (читает XKIT_REPO_URL
  из xkit.env).
- `nodes_ensure_pool`: провал применения конфига = явная ошибка (раньше
  маскировался «|| true» и node_add показывал «Нода подключена»); старый
  маршрут pool удаляется из routes.tsv (осиротевший location больше не живёт).
- Финал node_add показывает реальную схему панели ноды (https/http), а не http.
- `install.sh`: понятная ошибка, если забыли заменить `YOUR_USERNAME`;
  временный каталог чистится даже при запуске меню (exec убран).
- Установщики 3X-UI (мастер и нода) — mktemp вместо фикс-путей в /tmp;
  временные файлы скана ноды чистятся по trap даже при обрыве SSH.
- nginx-xray-manager-v3: дефолтный сайт nginx сносится только ПОСЛЕ успешного
  `nginx -t` + reload (раньше при ошибке конфига nginx оставался без server{});
  бэкап проверяется `tar tzf` (битые архивы удаляются); установщик 3X-UI в mktemp.

### Безопасность (v4.2, по результатам внешнего аудита)
- **RCE через api.ipify.org закрыт**: публичный IP валидируется (`is_ip`) и
  передаётся в heredoc для ufw через env, heredoc в кавычках.
- **SSH к нодам**: `StrictHostKeyChecking=accept-new` + постоянный
  `known_hosts` на ноду (не /dev/null), fingerprint показывается при добавлении;
  пароль — через `SSHPASS=... sshpass -e` (не виден в `ps`).
- **Панель ноды — HTTPS**: самоподписанный сертификат ставится автоматически,
  API панели ноды ходит по `https` (флаг `panel.tls` в реестре, авто-фолбэк на http).
- **Фикс**: реестр нод писался в несуществующую переменную (`KIT_NODES`) —
  ноды не сохранялись между запусками.
- Ссылки подписок: `path/host/sni` URL-энкодятся (`/` остаётся читаемым);
  email пользователя санитизируется (таб/перевод строки ломали subs.index).
- Локейшн подписок: `Referrer-Policy: no-referrer`, `X-Robots-Tag`, `access_log off`.
- Скан Reality: self-signed определяется по проверке цепочки openssl,
  а не по `CN==issuer`; `extfix` не трогает Reality/прямые инбаунды + подтверждение;
  `is_domain` требует буквенный TLD; свои серт/ключ проверяются на парность.
- В nginx-xray-manager-v3: `safe_name` в cli_switch/group_apply (path traversal),
  group_create через `jq -n` (не ломается JSON), guard длины файла в
  nginx_insert_block, временные файлы — `mktemp`+600.

### Веб-дашборд (пункт 23 / `xkit dash`)
Скрытая страница рядом с панелью: `https://ДОМЕН/d-<токен>/` — тот же принцип,
что у скрытой панели: без токена — обычный 404, в логи не пишется, noindex/
no-referrer/no-store/X-Frame-Options: DENY; опционально — allow только вашего
IP/CIDR (список через запятую). Сверху — **Basic Auth со случайными
логином/паролем** (генерируются при установке, показываются в финале и в
`/root/xkit-info.txt`).

Показывает:
- **Этот сервер (мастер)**: nginx / 3X-UI / API панели, uptime, load, RAM, диск, срок сертификата;
- **Ноды**: туннель (TCP-проба + латентность в мс), панель ноды (OK/ошибка входа/недоступна),
  потреблённый трафик по каждой ноде (сумма инбаундов её панели), срок аренды;
- **Инбаунды мастера**: трафик (↑/↓/Σ) и число клиентов каждого;
- **Топ-10 пользователей** по потреблённому трафику (+ срок их ключей);
- **Аренда**: срок мастер-сервера и каждой ноды с цветовой индикацией (зелёный
  >30 дней, жёлтый ≤30, красный ≤7 / просрочено).

Механика: `dash_gen` собирает данные (API панели + nodes.json + expiry.tsv) и
пишет **санитизированный** `data.json` (без privateKey/UUID/subId — только
агрегаты для UI; при недоступной панели данные прошлого построения
сохраняются со stale-меткой) + статичный `index.html` в `/var/lib/xkit/dash`
(750 root:www-data, файлы 640); cron (`xkit dash gen`, каждые 5 минут,
flock в subshell — открытые меню/cron не блокируют друг друга) обновляет
данные; JS на странице автообновляется каждые 30 сек. Внешних CDN нет — один файл.

```bash
xkit dash install     # установить (токен, Basic Auth, опц. allow IP/CIDR, nginx + cron)
xkit dash gen         # построить данные сейчас
xkit dash url         # показать URL
xkit dash rotate      # НОВЫЙ токен URL + новый логин/пароль (если засветились)
xkit dash uninstall   # убрать из nginx и cron (данные и сроки аренды остаются)
```

### Сроки аренды серверов (пункт 24 / `xkit expiry`)
Отдельный сохраняемый параметр (`/etc/xkit/expiry.tsv`, права 600): дата
окончания аренды мастер-сервера и каждой ноды + заметка (провайдер/тариф).
Срок ноды можно задать прямо при её добавлении (пункт 17) или позже:

```bash
xkit expiry set master 2027-05-01 "hetzner CX22"
xkit expiry set de1 2026-12-31 "netcup, к оплате до 20.12"
xkit expiry list     # таблица: до / осталось (цвет) / заметка
xkit expiry check    # ошибки: просрочено или ≤7 дней; предупреждения: ≤30
xkit expiry del de1
```

Сроки автоматически попадают в веб-дашборд (карточка мастера + колонка каждой ноды).

### Корректные конфиги и подписки «сразу в панели» (пункт 19)
- Каждому инбаунду проставляется **externalProxy** `{dest: ДОМЕН, port: 443|порт}` —
  панель сама генерирует ссылки/QR с доменом вместо 127.0.0.1 (для маршрутизируемых —
  443, для direct — реальный порт инбаунда).
- Нативный sub-сервис 3X-UI включается на `127.0.0.1:ПОРТ` и проксируется nginx'ом:
  рабочий URL подписки в панели: `https://ДОМЕН/sub-<token>/<subId>`.
- Файловые подписки xkit (`https://ДОМЕН/s-<token>/<subId>`) тоже работают — как резерв.

### Reality (пункты 14–16)
- **Свой сайт + сертификат** (лучший камуфляж, если есть домен): xkit ставит
  страницу-прикрытие в `/var/www/camo`, поднимает внутренний TLS-сервер nginx
  `127.0.0.1:8444` с вашим LE-сертификатом, Reality-inbound работает с
  `dest=127.0.0.1:8444, SNI=ваш домен`. Посторонние сканеры видят легитимный сайт.
- **Скан подсети**: TCP :443 (50 потоков) + openssl-проверки (TLS1.3, ALPN h2,
  X25519, self-signed, первый SAN без wildcard как SNI). Таблица с вердиктами,
  сохраняется в `/etc/xkit/reality-scan.tsv`.
- **By-IP**: нет домена — берите dest из готового списка (1.1.1.1/cloudflare-dns.com,
  tesla, samsung, …) или скана; ключи (pbk/sid) всегда видны в пункте 16, донастроить
  можно и из самой панели.

### Ноды и умная балансировка (пункты 17–18)
Схема: клиенты → мастер (nginx:443, pool-inbound за nginx) → xray **balancer** →
ноды (VLESS+Reality на :443 каждой ноды).
- Добавление ноды: по SSH (пароль — один раз, ставится наш ключ, пароль не хранится;
  `sshpass -e`, пароль не светится в `ps`) → неинтерактивная установка 3X-UI →
  случайные креды/порт панели + **HTTPS self-signed** → туннельный inbound
  VLESS+Reality → ufw (SSH+туннель; панель ноды — только с IP мастера, IP
  валидируется) → реестр `/etc/xkit/nodes.json` → аутбаунды и balancer в шаблоне xray.
  SSH-ключ хоста ноды пинуется (accept-new + постоянный known_hosts), fingerprint
  показывается при добавлении.
- **Маскировка на ноде** (camouflage выбирается при добавлении):
  1) `1.1.1.1` (дефолт, быстро и надёжно); 2) готовый список проверенных сайтов;
  3) **скан подсети С САМОЙ ноды** — сканер гоняется на ноде (кандидаты видны из её
  сети/гео, таблица та же: TLS1.3/H2/X25519/проверка цепочки); 4) **как на мастере** —
  тот же dest/SNI, что у Reality на мастере; 5) вручную. Сканеры видят на ноде
  TLS-хендлейк выбранного сайта — отдельный nginx/сайт на ноде не нужен.
- Стратегии: `roundRobin`, `random`, `leastPing`, `leastLoad` — две последние
  включают observatory/burstObservatory: xray сам переключает трафик на живые и
  быстрые ноды. (Сам 3X-UI переключением не занимается — это уровень xray-core;
  xkit автоматизирует шаблон конфига через API панели.)
- Health-check нод: TCP туннеля + `systemctl is-active x-ui` + логин в панель ноды.

### Как это устроено (безопасность)
- Панель: `webListen=127.0.0.1` + ufw deny → наружу не светится.
- Инбаунды ws/grpc/xhttp: `listen=127.0.0.1`, nginx принимает 443 и проксирует по путям.
- Наружу: 80 (redirect/ACME), 443 (TLS), SSH; для Reality — его публичный порт
  (открывается ufw автоматически при создании).
- Автопродление LE: certbot.timer + hooks stop/start nginx; IP-сертификаты —
  shortlived (6 дней), продление автоматическое.
