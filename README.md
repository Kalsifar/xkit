## 🎯 Что это

**XKIT** — интерактивное меню (и набор CLI-команд) для быстрого развёртывания и эксплуатации **VPN-сервера на базе 3X-UI + nginx** на Ubuntu 24.04+.

Одной командой XKIT ставит **3X-UI** (панель управления Xray), **nginx** с TLS, **certbot** с автопродлением сертификатов, и настраивает всё так, чтобы:

- панель и внутренние инбаунды **не светились наружу** — только `127.0.0.1` за nginx:443,
- **ссылки для клиентов** (подписки) генерировались с реальным доменом и путями, а не с `127.0.0.1:port`,
- снаружи открыт **только 443** (TLS), 80 (ACME redirect) и SSH.

Дополнительно XKIT умеет превратить одиночный сервер в **мастер с зарубежными нодами**: подключает удалённые серверы по SSH, ставит на них 3X-UI, создаёт VLESS+Reality-туннели, собирает `xray balancer` с умной стратегией и мониторит ноды через веб-дашборд и Telegram.

## 💡 Зачем

**Если у вас есть VPS с Ubuntu и вы хотите VPN-сервер, но не хотите:**

- вручную настраивать nginx + сертификаты + reverse-proxy для каждого инбаунда,
- следить, чтобы панель `3X-UI` не была доступна по `1.2.3.4:2053` из интернета,
- генерировать ссылки для клиентов вручную, потому что 3X-UI показывает `127.0.0.1:порт`,
- разбираться с `Reality` (`x25519`, `dest`, `SNI`, `shortIds`),
- писать свой `xray balancer` между несколькими серверами.

**XKIT делает это за вас.** Один сервер — 5 минут. Мастер с нодами — 20 минут.

## ⚡ Быстрый старт

### Установка

```bash
curl -fsSL https://raw.githubusercontent.com/kalsifar/xkit/main/install.sh | sudo bash
```

`install.sh` скачает `xkit.sh`, проверит SHA-256, отдаст установщику терминал (пароль `sudo` и все вопросы мастера установки работают даже при `curl | bash`) и запустит установку.

В конце установки XKIT спросит:

```
Что дальше?
  1) Одиночный сервер — автопроброс инбаундов за nginx (по умолчанию)
  2) Мастер с нодами — автопроброс, затем добавить зарубежные ноды
  3) Ничего — сделаю позже сам (xkit route / xkit nodes)
```

Выберите **1**, если у вас один сервер. Выберите **2**, если планируете подключать зарубежные ноды.

### Неинтерактивная установка (CI/cloud-init)

```bash
curl -fsSL https://.../install.sh | sudo bash -s -- -y
```

Флаг `-y` — согласие на все вопросы. Флаг `--force` — установка поверх существующей без меню.

### После установки

```bash
sudo xkit
```

Откроется меню в стиле `x-ui`.

## 🎛️ Режимы работы

XKIT понимает два режима и переключается между ними автоматически.

<table>
<tr>
<td width="50%" valign="top">

### 🌍 Одиночный сервер

- nginx:443 + 3X-UI на `127.0.0.1`
- Все инбаунды за nginx по путям
- Подписки через сам XKIT
- Подходит для личного VPN

```
клиент → nginx:443 → 3X-UI (127.0.0.1)
```

</td>
<td width="50%" valign="top">

### 🕸️ Мастер с нодами

- Всё из одиночного режима
- + N зарубежных нод с VLESS+Reality
- xray `balancer` между нодами
- `observatory` для leastPing/leastLoad
- Подписки с балансировкой

```
клиент → nginx:443 → balancer → нода1/нода2/нода3
```

</td>
</tr>
</table>

Удаление **последней** ноды автоматически возвращает сервер в одиночный режим (pool-инбаунд убирается целиком — клиенты не «застревают» на IP мастера).

## 🧩 Возможности по разделам

### Установка и панель

<details>
<summary><b>Пункт 1 — установка одним шагом</b></summary>

- **Пакеты**: nginx, certbot, jq, sqlite3, openssl, ufw, python3, cron.
- **SSL**: Let's Encrypt для домена / для IP (`shortlived` 6 дней) / свои файлы / самоподписанный.
- **3X-UI**: официальный инсталлятор в неинтерактивном режиме (случайные креды).
- **Панель прибивается к `127.0.0.1`** через `webListen` в БД — порт не светится.
- **UFW**: наружу только SSH + 80 + 443; порт панели закрыт `ufw deny` как страховка.
- **Preflight** до изменений: проверка занятых портов 80/443, свободного места ≥500 MB, RAM ≥400 MB, доступа к GitHub.
- **Живой UX**: спиннер на долгих операциях, индикатор шагов `[n/7]`, полный лог `/var/log/xkit-install-*.log` (600).
- **Идемпотентность**: повторный `xkit install` на установленном сервере предлагает меню (обновить / переустановить чисто / починить поверх), а не молча ставит поверх.

</details>

<details>
<summary><b>Пункт 12 — спрятать уже установленную панель</b></summary>

Если 3X-UI уже установлен и панель светится в интернет — этот пункт прибьёт её к `127.0.0.1`, настроит nginx, поставит UFW deny на порт панели и перевыпустит/использует существующий сертификат.

</details>

### Автопроброс инбаундов

<details>
<summary><b>Пункт 2 — главный пункт после установки</b></summary>

XKIT сам:

1. Подключается к API панели через `127.0.0.1`.
2. Получает список **всех** инбаундов.
3. **Классифицирует** каждый:
   - `ws` / `grpc` / `xhttp` / `httpupgrade` → **за nginx** (listen `127.0.0.1`, канонический путь `/xk-<net>-<port>/`),
   - `tcp+http` → за nginx с путём пользователя,
   - `Reality` / `UDP` / `raw TCP` → **direct** (не трогает, помечает «DIRECT» и объясняет почему).
4. Обновляет `listen` и пути в панели через API.
5. Строит **единый** конфиг nginx со всеми маршрутами.
6. `nginx -t` + reload; при ошибке — **реальный откат** к последнему бэкапу.
7. Перегенерирует подписки.

Инбаунды за nginx больше не видны снаружи по своему порту — только по `https://ДОМЕН/<путь>`.

</details>

### Пользователи и подписки

<details>
<summary><b>Пункты 3–6, 20 — создание, удаление, список, сброс трафика</b></summary>

- Создание пользователя в любом инбаунде: `UUID`, `subId`, квота (ГБ), срок жизни (дни), `flow` для Reality.
- Удаление пользователя **из всех** инбаундов и из подписок.
- Список пользователей с квотой, датой истечения, трафиком и ссылкой на подписку.
- Сброс трафика одного пользователя.

**Подписки** генерирует сам XKIT:

```
https://ДОМЕН/s-<token>/<subId>
```

Формат — стандартный v2ray-подписки (base64-список vless/vmess/trojan/ss ссылок). В ссылках — реальный домен и путь, а не `127.0.0.1:port`. Подходит для v2rayNG, Streisand, Hiddify, v2rayN.

Подписки перегенерируются автоматически каждый час через cron (`xkit sub -q`) и с `flock` — ручной запуск и cron не пересекаются.

</details>

<details>
<summary><b>Пункт 19 — корректные ссылки в самой панели (externalProxy)</b></summary>

Даже в самой панели 3X-UI ссылки будут корректными: пункт проставляет `externalProxy` каждому инбаунду (за nginx — `ДОМЕН:443`, direct — `ДОМЕН:порт`), включает нативный sub-сервис 3X-UI через nginx. Reality и прямые инбаунды не трогаются.

</details>

### Reality и маскировка

<details>
<summary><b>Пункты 14–16 — Reality-инбаунд, скан, ключи</b></summary>

- **Создание Reality-инбаунда** с выбором dest:
  1. **Свой сайт** на этом сервере (`127.0.0.1:8444` + ваш сертификат — лучший камуфляж),
  2. **Скан подсети** — ищем сайты с TLS 1.3 + H2 + X25519 + валидным сертификатом,
  3. **Готовый список** проверенных dest (1.1.1.1, tesla, samsung, …),
  4. **Вручную** — dest + SNI.
- **Скан подсети** — TCP-проба `:443` (50 потоков) + `openssl`-проверки. Таблица кандидатов с вердиктами. Сохраняется в `/etc/xkit/reality-scan.tsv`.
- **Показ ключей** — `publicKey`, `shortId`, `SNI`, `dest`, ссылки всех Reality-инбаундов.

</details>

### Ноды и балансировка

<details>
<summary><b>Пункты 17–18 — мастер с зарубежными нодами</b></summary>

**Добавление ноды по SSH:**

1. Пароль вводится **один раз** — XKIT ставит свой SSH-ключ на ноду, пароль не сохраняется (`sshpass -e`, не светится в `ps`).
2. `StrictHostKeyChecking=accept-new` + постоянный `known_hosts`, fingerprint хоста показывается — MITM не пройдёт.
3. Устанавливает 3X-UI на ноде (неинтерактивно), генерирует случайные креды/порт панели.
4. Включает самоподписанный HTTPS для панели ноды + **пин сертификата** (sha256) — API ноды защищён от MITM.
5. Создаёт VLESS+Reality-туннель на ноде.
6. **ufw на ноде**: SSH + туннель + панель только с IP мастера. Если публичный IP мастера не определён — панель **закрывается** (`ufw deny`), а не остаётся открытой.
7. Регистрирует ноду в реестре, собирает `xray balancer` и `observatory` на мастере.

**Стратегии балансировки:**

| Стратегия | Поведение |
|---|---|
| `roundRobin` | по кругу |
| `random` | случайно |
| `leastPing` | `observatory` пингует ноды, трафик идёт на самую быструю |
| `leastLoad` | burst-замеры, выбор наименее загруженной/быстрой |

**Health-check** нод: TCP туннеля + `systemctl is-active x-ui` + логин в панель ноды. SSH-провал не считается «нода мертва» — отдельный счётчик.

**Управление:**

- Список нод, удаление ноды, health-check.
- `repair` — переприменить конфигурацию после сбоя.
- `repin` — перепинить сертификат панели ноды (после перевыпуска серта).
- Стратегия балансировки.
- `убрать pool` — вернуть сервер в одиночный режим (явно).

</details>

### Веб-дашборд

<details>
<summary><b>Пункт 23 — статусы, трафик, сроки аренды</b></summary>

Секретная страница рядом с панелью: `https://ДОМЕН/d-<токен>/`

- **Этот сервер**: nginx, 3X-UI, API панели, uptime, load, RAM, диск, сертификат.
- **Ноды**: статус туннеля (TCP-проба + латентность), панель ноды (OK/fail), потреблённый трафик, срок аренды.
- **Инбаунды мастера**: трафик и число клиентов.
- **Топ-10 пользователей** по потреблённому трафику + срок их ключей.
- **Аренда**: мастер и каждая нода — цветовая индикация (>30 дней зелёный, ≤30 жёлтый, ≤7 / просрочено красный).

**Защита:**

- Basic Auth со случайными логином/паролем (генерируются при установке).
- Секретный URL-токен (без токена — 404).
- `noindex`, `no-referrer`, `no-store`, `X-Frame-Options: DENY`, `access_log off`.
- Опционально — `allow` только вашего IP/CIDR.
- Данные санитизированы: без `privateKey` Reality, `UUID/subId` клиентов.
- `flock` в subshell — cron обновляет каждые 5 минут, не блокируясь открытым меню.
- При недоступной панели прошлые данные не затираются (`stale: true`).

**Ротация** (`xkit dash rotate`) — новый URL-токен + новый логин/пароль, если засветились.

</details>

### Telegram-алерты

<details>
<summary><b>Пункт 26 — только то, чего 3X-UI не знает</b></summary>

XKIT присылает алерты, которых **не** умеет сам 3X-UI (бот-команды и уведомления о клиентах не дублируются):

- **Нода** упала / восстановилась (гистерезис: алерт со 2-й проверки подряд, один — на восстановление).
- **Аренда** истекает через ≤7 дней или истекла (дедуп: раз в сутки).
- **Сертификат** мастера истекает через ≤14 дней.
- **Дашборд** не обновлялся >25 мин.
- **Сервис** мастера (`nginx` / `x-ui`) упал / восстановился.
- **Диск**: ≥85% предупреждение, ≥95% тревога, «место освободилось».
- **IPv6**, новые правила — по необходимости.

**Доставка в два хопа:**

1. Напрямую с мастера.
2. Если `api.telegram.org` недоступен (типично для РФ) — **через ноды по SSH**: `curl` крутится на ноде, выход с её зарубежного IP.

Токен не попадает в `argv` (`curl -K -`). Cron каждые 10 минут (`/etc/cron.d/xkit-notify`), состояние алертов — `/etc/xkit/notify.state` (600).

</details>

### Сроки аренды

<details>
<summary><b>Пункт 24 — сколько осталось до конца оплаты VPS</b></summary>

Отдельный параметр (`/etc/xkit/expiry.tsv`, 600): дата окончания аренды **мастер-сервера** и **каждой ноды** + заметка (провайдер/тариф).

- Задать прямо при добавлении ноды или позже.
- Видно в `xkit expiry list`, `xkit expiry check` и на дашборде.
- Cron + Telegram-алерты за ≤7 дней.

</details>

### Бэкапы и восстановление

<details>
<summary><b>Пункты 8–9 — бэкап и restore</b></summary>

- **Автобэкап**: БД панели + конфиг nginx + серты + подписки + состояние XKIT. Ежедневно 03:17, хранение 14 дней.
- **Проверка целостности**: `tar czf` exit-code + `tar tzf`; битые архивы удаляются, а не отдаются как «успешный бэкап».
- **Restore**: precheck архива на `../` и абсолютные пути до `tar xzf`, распаковка с `--no-same-owner --no-overwrite-dir`.

</details>

### Обновление и переустановка

<details>
<summary><b>Пункт 22 + uninstall/reinstall</b></summary>

- **`xkit update [URL]`** — скачать `xkit.sh` из репозитория, сверить SHA-256, `bash -n`, атомарно заменить `/usr/local/bin/xkit`, оставить `.bak`. Конфиг/состояние/подписки не трогаются.
- **`xkit uninstall [--full]`** — бэкап обязателен, чистая зачистка следов XKIT. `--full` дополнительно сносит 3X-UI и `/etc/nginx/ssl`. **Никогда** не удаляются: бэкапы, `/etc/letsencrypt`, сам nginx, UFW-правила 22/80/443, xray на нодах.
- **`xkit reinstall`** — бэкап → `uninstall --full` → `one_step_install`. Для полного сброса.

</details>

## 🖥️ CLI-субкоманды

Для скриптов, cron и CI. Все — с валидацией и понятными сообщениями.

```bash
xkit                        # интерактивное меню

xkit reality                # Reality-wizard
xkit nodes [repair|repin]   # ноды
xkit extfix                 # externalProxy + подписки панели
xkit health                 # диагностика
xkit backup                 # бэкап сейчас
```

## ❓ FAQ

<details>
<summary><b>Нужен ли домен?</b></summary>

Нет. XKIT работает и на голом IP (`Let's Encrypt shortlived` для IP — 6 дней, авто-продление). Но для Reality свой сайт-прикрытие требует домена с валидным сертификатом.

</details>

<details>
<summary><b>Можно ли поставить XKIT на уже установленный 3X-UI?</b></summary>

Да, через пункт **2 «Привязать существующую установку»**. XKIT прочитает текущие настройки панели и спрячет её за nginx.

</details>

<details>
<summary><b>Что будет с моими клиентами, если я переустановлю XKIT?</b></summary>

- `xkit install` (поверх) — состояние (включая `SUB_TOKEN`) **сохраняется**, ссылки подписок не меняются.
- `xkit update` — обновляет только бинарник XKIT. Состояние/конфиг/подписки не трогаются.
- `xkit reinstall` — полный сброс: инбаунды/клиенты панели потеряются (но останутся в бэкапе), подписки пересоздадутся.

</details>

<details>
<summary><b>Почему клиенты не видят ноды в балансировке?</b></summary>

Стратегия `roundRobin` балансирует по каждому TCP-соединению — если у вас одно долгое соединение (WebSocket), оно «прилипает» к одной ноде. Для выбора быстрой ноды переключите стратегию на `leastPing` / `leastLoad` (пункт 18 → 4).

</details>

<details>
<summary><b>Как добавить ещё одну ноду?</b></summary>

Пункт **17**. Нода добавится в тот же пул (или в новую группу — если вы создаёте их вручную). При следующем соединении клиент попадёт на новую ноду.

</details>

<details>
<summary><b>Что если у меня упал мастер?</b></summary>

Клиенты отвалятся, пока мастер не поднимется. Ноды автономны — xray на них продолжает работать, но клиенты подключаются к мастеру. Бэкап (пункт 8) + восстановление (пункт 9) на новом сервере.

</details>
